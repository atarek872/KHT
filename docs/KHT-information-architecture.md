# KHT — Information architecture v1

الحالة: هيكل صفحات وتجربة شراء مقترحة فقط. لا واجهات أو متجر أو مدفوعات منفذة.

## 1. نطاق التجربة والافتراضات

الهدف: تعريف الزائر بالهوية ثم مساعدته على اختيار تيشرت أو سوت أو بنطلون، تحديد المقاس، وإتمام طلب مفهوم التكاليف والحالة.

افتراضات قابلة للتعديل: العربية لغة الواجهة الأولى، ومصر/الجنيه المصري سياق أولي للأمثلة، وشراء كضيف دون إنشاء حساب. اللغة والسوق وطرق الدفع النهائية لم تُحسم. مصطلح «سوت» يُعامل مؤقتًا كطقم ملابس؛ تكوينه وطريقة اختيار مقاساته يحتاجان بيانات المنتجات. اسم DROP 001 مثال من الـbrief وليس تأكيدًا لوجود مجموعة منشورة.

## 2. خريطة الموقع

الأقواس تدل على محتوى متغير، وليست صفحات منفصلة تُبنى لكل منتج. صفحات التأكيد ومتابعة الطلب لا تكشف بيانات شخصية بمجرد معرفة رقم الطلب؛ تتطلب جلسة مصرحًا بها أو رابطًا آمنًا أو تحققًا مناسبًا.

الحساب، المفضلة، الولاء، تقييمات العملاء، الاشتراك التسويقي، والتوصيات الشخصية خارج النسخة الأولى. لا صفحة Drops فارغة؛ رابط الإصدار يظهر عند وجود محتوى حقيقي.

## 3. التنقل وتصنيف المحتوى

**Desktop:** اللوجو يرجع للرئيسية؛ «تسوق» يفتح قائمة صغيرة: كل المنتجات، تيشرتات، سوت، بناطيل. بجواره الإصدار الحالي وعن KHT. البحث والسلة مع عدد القطع في الطرف الآخر. لا حاجة لقائمة ضخمة لثلاثة أنواع منتجات.

**Mobile:** اللوجو + فتح القائمة + البحث + السلة. القائمة تحتوي روابط التصنيفات والدعم؛ السلة تظل خارجها. زر إغلاق واضح، مع بقاء موضع التصفح عند العودة.

**Footer:** تسوق؛ مساعدة تشمل المقاسات والشحن والاسترجاع والمتابعة والتواصل؛ ثم الخصوصية والشروط وحسابات البراند الفعلية. لا صف شعارات دفع قبل تحديد الوسائل المتاحة.

التصنيف يصف نوع القطعة؛ الـDrop يجمع قطعًا من تصنيفات متعددة؛ الـCampaign محتوى تصويري مرتبط بالإصدار. المنتج يمكن أن ينتمي لتصنيف وإصدار دون تكرار صفحة تفاصيله.

مسار تنقل المنتج: الرئيسية / التصنيف / اسم المنتج. الرجوع لقائمة المنتجات يستعيد الفلاتر والترتيب وموضع التصفح.

## 4. ترتيب الرئيسية

1. **Header داكن:** تنقل مختصر ووصول مباشر للسلة.
2. **Hero داكن:** صورة حملة كبيرة + BLACK. WHITE. LINE. + وصف قصير معتمد + SHOP DROP 001 → إذا وُجد إصدار، أو «تسوق المجموعة» إلى /shop. الخط الأبيض يمتد من تكوين الصورة للمساحة المحيطة.
3. **منتجات الإصدار بخلفية فاتحة:** حتى 3–6 قطع فعلية، الاسم والسعر واضحان، ورابط لعرض المجموعة بالكامل. هذه أول نقطة مقارنة للمنتجات.
4. **تصفح حسب القطعة على خلفية داكنة:** ثلاث صور تحريرية للتيشرتات والسوت والبناطيل؛ روابط مباشرة، بلا صناديق خدمات أو مزايا عامة.
5. **تفصيلة الخط:** لقطة قريبة وصياغة قصيرة عن التفصيل الفعلي، ورابط «عن KHT». يحذف القسم إن لم يوجد محتوى أصلي مناسب.
6. **Footer داكن:** المساعدة والسياسات والتواصل.

لا فيديو تلقائي أو شاشة تحميل افتتاحية أو نافذة اشتراك تغطي أول زيارة. لو كان الكتالوج صغيرًا، لا نكرر القطع نفسها في عدة أقسام.

### Wireframes تنظيمية

الرسومات التالية تمثل توزيع المساحات فقط. ترتيب أعمدة الواجهة العربية من اليمين، والنص الإنجليزي يحتفظ باتجاهه.

```text
HOME — DESKTOP
┌──────────────────────────────────────────────┐
│                   Header                     │
├─────────────────────────┬────────────────────┤
│                         │ Campaign title     │
│     Campaign image      │ Short copy         │
│                         │ Primary CTA        │
│        White line continues into space       │
├──────────────────────────────────────────────┤
│       Product       Product       Product    │
├──────────────────────────────────────────────┤
│              Three category images           │
├──────────────────────────────────────────────┤
│             Line detail + brand story        │
├──────────────────────────────────────────────┤
│                    Footer                    │
└──────────────────────────────────────────────┘

HOME — MOBILE
┌───────────────────────┐
│        Header         │
│    Campaign image     │
│    Title + one CTA    │
│     White line        │
│  Product  │  Product  │
│    Category images    │
│      Line detail      │
│        Footer         │
└───────────────────────┘
```

ارتفاع الـHero على الهاتف مرن حسب الصورة والنص، مع إظهار الإجراء دون فرض شاشة طويلة. لا يعتمد عرض العنوان على تغطية صورة الملابس.

## 5. الكتالوج والبحث والإصدار

**الكتالوج:** عنوان وعدد نتائج؛ تصنيفات؛ فلاتر للمقاس والتوافر والسعر عند الحاجة؛ ترتيب «مختارات KHT»، الأحدث، السعر تصاعديًا أو تنازليًا. اللون لا يظهر كفلتر إذا كانت كل القطع بنفس اللون. لا ترتيب «الأكثر مبيعًا» دون بيانات.

شبكة 3 أعمدة Desktop وعمودين للهاتف والتابلت. تعرض الدفعة الأولى حتى 12 منتجًا. إذا زاد العدد يظهر «عرض المزيد» مع حفظ حالة الصفحات في الرابط والعودة؛ لا تمرير لانهائي يمنع الوصول للسياسات. الفلاتر أعلى الشبكة على Desktop، وفي لوحة واضحة مع «عرض النتائج» و«مسح الفلاتر» على الهاتف.

البطاقة تفتح المنتج لاختيار المقاس؛ لا إضافة مباشرة تختار مقاسًا افتراضيًا. المخزون يظهر عند المقاس الفعلي، والأسعار المختلفة تعرض «يبدأ من» ثم السعر الدقيق بعد الاختيار.

**البحث:** فتح حقل بحث سريع، إدخال اسم أو نوع القطعة، ثم صفحة نتائج قابلة للمشاركة. تستخدم النتائج نفس شبكة الكتالوج مع ترتيب الصلة أولًا. الحالة الفارغة: «مفيش منتجات مطابقة. جرّب اسم القطعة أو امسح الفلاتر» مع إجراء واضح.

**الإصدار:** صورة وعنوان ووصف قصير، ثم منتجات الإصدار فقط. لا عد تنازلي أو عبارة «كمية محدودة» دون أساس فعلي. القطع النافدة تبقى مع حالتها إذا كان الاحتفاظ بأرشيف الإصدار مفيدًا، مع رابط لقطع متاحة.

## 6. صفحة المنتج

الخلفية Off White والصور على Gray 100. Desktop: معرض صور نحو 60% من العرض، ومعلومات الشراء نحو 40% عند بداية اتجاه القراءة. Mobile: صور قابلة للسحب مع عداد، ثم الاسم والسعر والاختيارات وزر الشراء، ثم التفاصيل.

ترتيب المعلومات:

1. مسار التنقل واسم المنتج والسعر بالعملة المحددة.
2. وصف قصير للقَصّة والخامة من البيانات الحقيقية.
3. اسم اللون، والاختيار إذا توفرت بدائل.
4. المقاس كأزرار واضحة، وبجواره «دليل المقاسات» الذي يفتح جدول القطعة.
5. حالة توافر المقاس وزر «أضف للسلة»؛ لا تحديد مقاس تلقائيًا.
6. ملخص الشحن والاسترجاع المعتمد وروابط التفاصيل، قرب قرار الشراء.
7. تفاصيل الخامة والعناية والقياسات داخل أقسام قابلة للفتح.

إذا كان السوت طقمًا بمقاس موحد، يوضح المحتوى القطع المشمولة. إذا كان لكل جزء مقاس مستقل، تظهر اختيارات «مقاس الجزء العلوي» و«مقاس البنطلون» وتتبع السلة نفس التكوين. هذا القرار مرتبط بطريقة بيع المنتج ولا يُفترض عند التنفيذ.

على الهاتف يظهر شريط شراء بعد خروج الزر الأصلي من المشهد. قبل اختيار المقاس يكون إجراؤه «اختار المقاس» وينقل إلى الاختيار؛ بعده يعرض السعر و«أضف للسلة». لا يغطي أي محتوى.

عند نجاح الإضافة تفتح السلة الجانبية ويظل المنتج خلفها. عند فشلها تبقى الاختيارات ويظهر سبب قابل للمعالجة. لا تأكيد نجاح سابق لنتيجة العملية الفعلية.

## 7. السلة وإتمام الطلب

**السلة الجانبية:** تأكيد القطعة المضافة، الصورة، الاسم، المقاس/تكوين الطقم، الكمية، السعر، المجموع الفرعي. «إتمام الطلب» إجراء أساسي، «عرض السلة» للمراجعة، و«متابعة التسوق» للإغلاق.

**صفحة السلة:** تعديل الكمية وإزالة القطع، ملخص واضح، ورسالة «تكلفة التوصيل تُحدد بعد اختيار العنوان» حين لا يمكن حسابها بعد. السلة الفارغة تعرض رابط التسوق. المخزون أو السعر المتغير يحتاج تنبيهًا ومراجعة قبل المتابعة؛ لا استبدال مقاس تلقائي.

**إتمام الطلب المقترح:** صفحة واحدة بثلاث مجموعات، تتوسع تدريجيًا على الهاتف. الشراء كضيف هو اقتراح النسخة الأولى، ويثبت مع منصة البيع قبل التنفيذ.

| المجموعة | المعلومات والقرار |
| --- | --- |
| 1. بياناتك وعنوانك | الاسم، الهاتف، قناة تأكيد الطلب المطلوبة، المحافظة/المدينة والعنوان وفق سوق البيع، ملاحظات اختيارية |
| 2. التوصيل والدفع | وسائل متاحة فعلًا لهذا العنوان، تكلفة ومدة كل توصيل، اختيار طريقة دفع، بيانات فوترة مختلفة عند الحاجة |
| 3. مراجعة وتأكيد | القطع والمقاسات والعنوان ووسيلة الدفع، ملخص كل التكاليف، وروابط تعديل البيانات والسياسات |

المجموع الفرعي والخصم والتوصيل وأي رسوم مطبقة تظهر قبل التأكيد، ويظهر الإجمالي النهائي قرب الزر. ملخص الطلب بجانب النموذج على Desktop، وقابل للفتح أعلى الصفحة على الهاتف، ثم يظهر الإجمالي مجددًا قبل التأكيد.

للوسيلة الإلكترونية تكون تسمية الإجراء «متابعة للدفع» عند الانتقال لبوابة، أو «ادفع [الإجمالي]» عند تنفيذ الدفع مباشرة. للدفع عند الاستلام تكون «تأكيد الطلب» إذا اعتُمدت الوسيلة فعلًا. لا نفترض إتاحة بطاقة أو محفظة أو دفع عند الاستلام.

```text
Discover → Category / Drop / Search → Product → Select size
                                                    ↓
Continue shopping ← Cart drawer ← Add to cart succeeds
                        ↓
                  Cart / Checkout
                        ↓
             Address → Delivery & payment → Review
                        ↓
              Order result → Track order
```

## 8. النتائج والحالات البديلة

| الحالة | ما يراه العميل وما يستطيع فعله |
| --- | --- |
| تحميل المنتجات | مساحات ثابتة بحجم الصور ومؤشر تحميل مختصر |
| فشل التحميل | رسالة محددة و«حاول مرة أخرى»، مع بقاء البحث والفلاتر |
| لا نتائج | عدد صفر، إزالة الفلاتر أو تغيير البحث |
| مقاس نافد | المقاس ظاهر بوصف «غير متاح»، واقتراح اختيار متاح |
| فشل الإضافة | اختيارات محفوظة ورسالة بجوار إجراء الإضافة |
| نفاد قطعة أثناء الشراء | تحديد القطعة المتأثرة، تعديل الكمية أو حذفها، ثم مراجعة الإجمالي |
| عنوان خارج التغطية | شرح عدم توفر التوصيل وإمكانية تعديل العنوان |
| خطأ نموذج | رسالة عند الحقل وملخص أخطاء ينقل لأول حقل يحتاج تعديلًا |
| فشل أو إلغاء الدفع | بقاء السلة والبيانات، محاولة أخرى أو اختيار وسيلة متاحة |
| نتيجة الدفع غير مؤكدة | «جارٍ التحقق من حالة الدفع»؛ التحقق من الطلب قبل السماح بمحاولة قد تكرر الخصم |
| نجاح إنشاء الطلب | رقم المرجع، القطع، المبلغ، العنوان، حالة الدفع الفعلية، والتوصيل المتوقع إن توفر |
| دفع عند الاستلام | «تم استلام طلبك» و«الدفع عند الاستلام»، دون وصفه بأنه مدفوع |
| متابعة الطلب | الحالة الحالية والخطوة التالية وقناة الدعم بعد تحقق مناسب |

بعد إنشاء الطلب بنجاح تُفرغ السلة الخاصة به ويظل ملخص الطلب قابلًا للرجوع. صفحة التأكيد تميز بين «طلب مؤكد» و«الدفع قيد الانتظار» و«مدفوع»؛ لا تعرض نجاحًا ماليًا مبنيًا على العودة من بوابة الدفع وحدها.

## 9. المحتوى والبيانات اللازمة

| الكيان | البيانات اللازمة للتصميم النهائي |
| --- | --- |
| البراند | ملف اللوجو، صور توضح الخط، وصف البراند، روابط التواصل |
| المنتج | الاسم، التصنيف، وصف القَصّة، الخامة، العناية، الصور ووصفها، الإصدار إن وجد |
| النسخة القابلة للبيع | SKU، المقاس، اللون، السعر والعملة، التوافر، تكوين الطقم عند الحاجة |
| دليل المقاسات | قياسات كل نوع بالسنتيمتر وطريقة القياس؛ قياس الموديل إن كان متاحًا فعلًا |
| الإصدار | الاسم، صورة الحملة، النص، المنتجات المرتبطة، حالة النشر |
| البيع والتوصيل | السوق، مناطق التغطية، التكلفة والمدد، وسائل الدفع، قواعد الخصم إن وجدت |
| الدعم والسياسات | جهة التواصل، إجراءات الاستبدال والاسترجاع، الخصوصية والشروط المعتمدة |
| الطلب | مرجع آمن، القطع ونسخها، ملخص المبالغ، حالات الطلب والدفع والتوصيل |

إدارة المنتجات والأسعار والمخزون والطلبات والشحن مطلوبة تشغيليًا عند بناء المتجر، لكن هذه الوثيقة لا تفترض لوحة إدارة مخصصة أو منصة معينة. المحتوى التجاري المتغير يجب أن يأتي من مصدر البيع المعتمد لاحقًا.

## 10. قرارات قبل الانتقال للتنفيذ

المطلوب لتثبيت النسخة النهائية: المرجع المرئي المذكور سابقًا، صور المنتجات واللوجو، معنى السوت وتكوين المقاسات، لغة/لغات الموقع وسوق البيع، الأسعار والعملة، سياسة الشحن والاسترجاع ووسائل الدفع، ومنصة تشغيل المتجر.

هذه نقاط مفتوحة موثقة وليست عائقًا أمام مراجعة نظام التصميم الحالي. عند بدء التنفيذ فقط تُراجع مراجع storefront-best-practices الخاصة بكل صفحة ومكون، ويُتحقق من تكامل منصة البيع المختارة. لم يتم اختيار إطار عمل أو تثبيت مكتبات أو إنشاء كود أو نشر موقع في هذه المرحلة.
